# 6. WHAT TO MEASURE

For each of the five calls, record:

### Invocation

* call number
* Claude CLI exit status
* elapsed time
* whether the outer JSON envelope was successfully parsed

### Outer envelope

Record only safe metadata:

* outer JSON parse: PASS/FAIL
* `is_error`: true/false
* whether a `result` field was present
* result data type

Do NOT record:

* credentials
* authentication tokens
* session identifiers
* sensitive environment values

### Inner result

For the `result` field record:

* result type
* character count
* first safe character(s)
* last safe character(s)
* whether it begins as JSON
* whether it contains Markdown code fences
* whether explanatory prose appears before JSON
* whether explanatory prose appears after JSON
* direct `json.loads(result)` result: PASS/FAIL

Do not unnecessarily persist the entire raw Claude response.

If a response-format anomaly occurs, capture only enough safe evidence to establish the observed format.

---

# 7. FORMAT CLASSIFICATION

Classify every call as one of:

### FORMAT-A — CLEAN JSON

The `result` is directly parseable JSON with no Markdown wrapper or explanatory prose.

### FORMAT-B — MARKDOWN-WRAPPED JSON

The result contains JSON inside Markdown code fences.

### FORMAT-C — PROSE + JSON

The result contains explanatory prose before or after the JSON.

### FORMAT-D — INVALID JSON

The result is neither directly parseable JSON nor a safely recognizable JSON-wrapped format.

### FORMAT-E — PROVIDER/INVOCATION FAILURE

The Claude invocation itself fails before a usable result is obtained.

Do not infer the cause. Report observed facts separately from hypotheses.
