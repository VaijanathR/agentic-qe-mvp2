* defect_history

* security_impact
* customer_impact

* evidence/source attribution

**RBTP**
= which tests should be prioritized and why.

**Dependency/Reusability Matrix**
= which artifacts/tests depend on, overlap with, sequence with, or can reuse other assets.

* stable testcase ID
* requirement IDs
* journey ID
* scenario type
* preconditions
* steps
* expected results
* test-data references
* priority
* source attribution

# 6. RBTP — RISK-BASED TEST PRIORITIZATION

Implement RBTP as a persistent artifact.

RBTP must operate on persisted testcases.

It should support evidence-backed prioritization using available information such as:

* business criticality
* customer impact
* likelihood
* change impact
* defect history
* dependency impact
* security impact
* other explicitly evidenced risk factors

Do NOT fabricate risk values.

If evidence is insufficient:

* mark the factor unknown
* preserve the limitation
* do not invent a score

The implementation must make the prioritization explainable.

A user must be able to answer:

> Why is TC-X P0 while TC-Y is P2?

from the persisted RBTP artifact.

# 7. DEPENDENCY / REUSABILITY MATRIX

Create a persisted Dependency/Reusability Matrix.

Its purpose is NOT risk prioritization.

It must identify, where evidence supports it:

* testcase dependencies
* requirement dependencies
* data dependencies
* automation dependencies
* shared setup
* shared authentication/session requirements
* reusable Playwright components
* duplicate/overlapping testing
* sequencing constraints
* opportunities for safe reuse

Do not create abstractions merely for architectural appearance.

Only identify reuse where there is actual repetition or evidence-backed commonality.
