# Objective

Create the canonical, governed specification for:

**CP-MVP2-04 — LLM Test Data Generation**

The specification must define how Agentic QE generates governed, requirement-aligned test data for the testcases produced by CP-MVP2-03.

The specification must preserve the architecture:

`APPROVED SRS → GOVERNED RAG → LLM TESTCASE GENERATION → DETERMINISTIC TESTCASE VALIDATION → LLM TEST DATA GENERATION → DETERMINISTIC TEST DATA VALIDATION`

The specification must clearly distinguish:

* requirement-derived data constraints
* testcase-derived data needs
* valid/positive data
* alternate data
* exceptional/negative data
* boundary data
* invalid data
* authorization/role-related data where justified
* dependency-related data
* uniqueness constraints
* data combinations
* data reuse
* data isolation
* generated data versus externally supplied/environmental data

---

# Critical governance principle

**The Approved SRS remains the ultimate source of truth.**

The LLM must NOT invent business rules merely because they appear plausible.

The LLM may reason about test data only from:

1. Approved SRS
2. governed MVP2 Knowledge Base/RAG context
3. validated CP-MVP2-03 testcase information
4. explicitly supplied deterministic constraints

If required information is unavailable or ambiguous:

`UNSUPPORTED / NEEDS CLARIFICATION`

must be produced instead of fabricated data.
