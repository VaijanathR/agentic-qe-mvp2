## Architecture Decisions

1. **`llm/client.py` not modified** — a new file, `llm/automation_client.py`, reuses `ClaudeProviderError` and the identical Claude Pro subscription/subprocess-safety mechanism, since `LLMClient.propose_testcases()`'s contract is inapplicable (same precedent as CP-MVP2-04's `llm/test_data_client.py`).
2. **A narrower LLM contract than CP-MVP2-04's** — `propose_steps()` returns action-structure only (`action_type`, `field_name`, `synchronization_strategy`, narrative `assertion_condition`); it never returns a locator or a field value. This directly reflects the frozen specification's repeated, explicit prohibition on locator fabrication.
3. **The one mandatory `BUSINESS_REQUIRED` assertion is always assembled deterministically** from the anchor testcase's own `expected_result` — never contingent on the LLM proposing one. Any LLM-proposed assertion narrative is classified `TECHNICAL_USEFUL` and never counts toward coverage.
4. **Locator evidence is read directly from `knowledge/historical/discovery_evidence/captures/checkout_00.html` at call time**, via regex confirmation against the real file content — never a cached/hardcoded string presented as evidence without a fresh check.
5. **Conservative load-bearing rule**: every `FILL`/`CLICK`/`SELECT` step is treated as load-bearing; one `UNSUPPORTED` locator anywhere among them makes the whole artifact `UNSUPPORTED_NEEDS_CLARIFICATION`, never partially `ACCEPTED`.
