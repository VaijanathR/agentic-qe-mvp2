## Specification Design Decisions (documented in the specification itself)

1. **Three logical schema levels** (`PlaywrightArtifact` / `PlaywrightStep` / `LocatorSpec`+`Assertion`), extending the two-level precedent CP-MVP2-04 established — justified because a Playwright scenario is inherently an *ordered sequence* of actions, each potentially needing its own locator, which a two-level schema cannot represent.
2. **Locator evidence is read directly from the raw historical discovery captures on disk, never via `KnowledgeBase`** — because CP-MVP2-02 deliberately excludes historical-discovery content from the queryable RAG corpus (verified in `knowledge/lib/validate.py`). This is stated as a hard architectural constraint, not a design preference.
3. **Reused governance vocabulary** (`ACCEPTED`/`REJECTED`/`QUARANTINED`/`UNSUPPORTED_NEEDS_CLARIFICATION`/`DUPLICATE`/`POSSIBLE_DUPLICATE`) rather than inventing parallel terminology, per the task's own explicit instruction.
4. **Artifact-level (not step-level) acceptance**, with a "load-bearing step" rule (sec. 12.1): any `UNSUPPORTED` step needed to reach or verify the core expected result makes the whole artifact `UNSUPPORTED`, while non-load-bearing step/locator statuses are still retained for future RCA diagnostic value (sec. 14) — a new nuance this checkpoint required that CP-MVP2-03/04 did not, because they have no equivalent "sequence of dependent actions" structure.
5. **Assertion classification with a coverage-eligibility flag** (`BUSINESS_REQUIRED`/`TECHNICAL_USEFUL`/`DIAGNOSTIC_OPTIONAL`, only the first counting toward coverage) — directly satisfies the task's explicit instruction that "optional diagnostics cannot falsely inflate requirement coverage."
